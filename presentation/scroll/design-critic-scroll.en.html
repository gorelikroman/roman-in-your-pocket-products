How to ask

In plain words — something for every role

The critic works out what you need. To bring in a product, just name it: “in Reboost”.

Look at my onboarding mockup

→ a list of what to fix before handoff, from urgent to minor

Make three options for the home screen

→ three different directions and what each one is good at

Did I miss anything on this screen?

→ which states are missing: empty, loading, error, no access

It’s too loud, calm it down

→ step-by-step changes and what exactly is “shouting”

Build the sort menu properly

→ ready code: smooth opening, keyboard support, accessibility

Check my branch before review

→ what to fix in the UI code and why

Why does this button feel sluggish?

→ there is no response to the press, and how to add one

Which states does this component need?

→ loading, error, empty, disabled, with examples

What did I miss in the orders screen ticket?

→ scenarios and states the ticket doesn’t cover

Write acceptance criteria for the product card

→ points you can actually test, not “should be easy to use”

Can insurance be switched on by default?

→ no: a paid option can’t be chosen for the user, and why

How do we know the redesign worked?

→ what to measure, from which baseline, and when to roll back

What should I test in Reboost checkout?

→ a list of checks with steps and expected results

Make test cases for TestRail

→ a table you can import right away

Write up this bug

→ a bug report that cites the rule, so nobody argues

Check this page on a phone

→ clipped text, tiny buttons, pale labels

Explain why this screen is awkward

→ in plain words, tied to how perception works

Compare two options — which is better?

→ a choice with reasons, not “I just like it more”

What should we fix first?

→ the most urgent and cheapest fixes on top
